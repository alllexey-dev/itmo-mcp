# ИСУ (isu.ifmo.ru)

## 1. Назначение

ИСУ - информационная система университета на Oracle APEX. Программного API для студентов у неё нет: данные берутся
из HTML-страниц приложения APEX 2143. Наш опыт - проверка в itmo-widgets-backend, что преподаватель вёл занятия у
автора отзыва: по номеру потока читаются его участники и преподаватели. В spike обычный аккаунт открывал и чужие
(где он не участник), и прошлые потоки.

## 2. Хосты и авторизация

| Что | Значение |
|---|---|
| Хост | `https://isu.ifmo.ru` |
| Страницы | `/pls/apex/f?p=<app>:<page>:<session>:...` |
| Приложение | 2143 (потоки и расписание); с сайта и из приложения ещё ведут ссылки на APEX 2156 и 2437 и фото `/userpics/` |
| Вход | SSO-cookie `KEYCLOAK_IDENTITY` от ITMO.ID, см. [../auth.md](../auth.md) |

Вход (статус: проекты):

1. Положить `KEYCLOAK_IDENTITY` в cookie jar для `https://id.itmo.ru/auth/realms/itmo/` (домен `id.itmo.ru`, путь
   `/auth/realms/itmo/`, Secure).
2. `GET https://isu.ifmo.ru/pls/apex/f?p=2143:1` с User-Agent браузера и `Accept: text/html`, редиректы проходить
   вручную (бэкенд ограничивает их десятью). Цепочка идёт через id.itmo.ru, около семи редиректов.
3. По пути ИСУ ставит свои cookie: `ISU_AP_COOKIE`, `ORA_WWV_RAC_INSTANCE`, `REMEMBER_SSO`, `ISU_LIB_SID`.
4. Номер APEX-сессии - третья часть `f?p=2143:<page>:<session>` в итоговом URL. Регулярное выражение из
   `IsuClient.kt`: `[?&]p=2143:[^:&]*:([0-9]+)`.
5. Keycloak при входе переиздаёт `KEYCLOAK_IDENTITY` (`Set-Cookie` с `Max-Age`): сохранять последний.

Признаки исходов:

| Исход | Признак |
|---|---|
| Cookie истекла | Итоговый URL на `id.itmo.ru` под `/auth/realms/itmo/` или на странице есть форма `#kc-form-login` |
| Сбой входа | Статус не 200 или в итоговом URL нет номера сессии |
| Сессия потеряна | Запрос страницы закончился на id.itmo.ru, на форме Keycloak, вне `/pls/apex/` или без номера сессии; войти заново и повторить один раз |
| Тихая замена сессии | При живой cookie APEX сам подменяет неизвестный номер сессии и отдаёт страницу; брать новый номер из итогового URL |

Тонкость Java: `Set-Cookie` Keycloak с `Max-Age` `java.net.CookieManager` разбирает как cookie RFC 2965 и отправляет
обратно в кавычках с `$Version`. Нужно хранить cookie с версией 0, чтобы уходил обычный `name=value`.

## 3. Ручки

| Метод | Путь | Что делает | Статус |
|---|---|---|---|
| GET | `/pls/apex/f?p=2143:1` | Вход: даёт номер APEX-сессии | проекты |
| GET | `/pls/apex/f?p=2143:GR:<session>::NO::GR_TYPE,GR_DATE,ID_POTOK,ID_DISTP:potok,<dd.MM.yyyy>,<flow>,` | Список участников потока на дату | проекты |
| GET | `/pls/apex/f?p=2143:15:<session>::NO::SCH,SCH_POTOK_ID,SCH_TYPE,SCH_WEEK,SCH_ID,SCH_FOUND:1,<flow>,5,2,,TRUE` | Расписание потока с преподавателями | проекты |

`<flow>` - `flow_id` из расписания my.itmo.ru (`/api/schedule/schedule/personal`). `ID_DISTP` можно оставить пустым.

## 4. Модели и правила

Список потока (страница `GR`):

- Таблица с атрибутом `summary`, начинающимся с `Список потока` (дальше дата).
- Номер ИСУ участника - ячейки `td[headers=ЧЛВК_ИД]`, группа - `td[headers=ГРУППА]`. В сыром HTML имена заголовков
  закодированы HTML-сущностями: сначала раскодировать.
- Пустой поток - `<span class="nodatafound">`.
- Не больше 250 строк: это APEX classic report без ссылок пагинации, запрос строк после 250 возвращает пустую
  таблицу. Бэкенд всё равно идёт по ссылкам `pg_min_row`, если они появятся (не больше 20 страниц).

Преподаватели потока (страница 15):

- Ссылки вида `PID:<isu>` в расписании потока; номер - группа регулярного выражения `PID:([0-9]+)`.
- Работает и для прошлых потоков. Карточка "Информация о потоке" преподавателя не содержит (только дисциплина,
  реализатор, вид, семестр, лимит).

Правила itmo-widgets-backend:

- Пауза 2 с между запросами, таймауты 10 с на соединение и 30 с на запрос, тело не больше 5 MiB.
- Читаются и хранятся только номера: имена, группы и фото не читаются.
- Кэш: преподаватели потока 30 дней, участники 1 день.
- Чтобы cookie не истекла без дела, раз в 7 дней выполняется вход.

## 5. Покрытие в itmo-mcp

Нет: владелец решил пока не подключать ИСУ. Для подключения понадобился бы `KEYCLOAK_IDENTITY`; при входе только по
refresh token его нет.

## 6. Риски и открытые вопросы

- Это разбор HTML: любое изменение страниц APEX (атрибуты `summary` и `headers`, параметры страниц) ломает чтение без
  предупреждения.
- Страницы показывают чужие персональные данные (составы потоков); при любом использовании нужно читать и хранить
  минимум.
- Списки потоков больше 250 человек читаются не полностью.
- Без `KEYCLOAK_IDENTITY` (только refresh token) в ИСУ не войти; работает ли вход в ИСУ по cookie, полученной без
  `rememberMe=on`, не проверялось.
- Что дают APEX-приложения 2156 и 2437, на которые ссылаются сайт и приложение, не изучалось.
- Связан ли клиент `isu` из `ALLOWED_AZP` сайта my.itmo.ru с этой системой, неизвестно.
