# Общие правила ответов

Как устроены ответы сервисов, как распознавать ошибки, в каких форматах ходят даты и какие есть причуды.
Примеры значений синтетические.

## Конверты

| Конверт | Форма | Успех | Где встречается | Статус |
|---|---|---|---|---|
| `ResultResponse` | `{"error_code", "error_message", "result"}` | `error_code` равен 0 или `null` | Большинство разделов `my.itmo.ru/api`; `null` вместо 0 у бронирования, заявок v2 (`/api/requests/v2/`), согласий (`/api/agreements/`), индивидуального плана | проверено |
| `DataResponse` | `{"code", "data", "message"}` | `code` равен 0 | Расписание: `/api/schedule/schedule/personal`, `/api/schedule/meta/time_slots` | проверено |
| `SimpleResponse` | `{"response": ...}` | HTTP 2xx | `qr.itmo.su/v1/user/pass` | проекты |
| Голый JSON | Объект или массив без обёртки | HTTP 2xx | БАРС (`/backend/rest/*`), навигатор (`/api/navigator/buildings`) | проверено |
| Ошибка Spring | `{"timestamp", "status", "error", "message", "path"}` | - | Ошибки БАРС | проверено* |
| Ошибка FastAPI | `{"detail": ...}` | - | Ассистент (`/api/assistant/*`), например при отсутствии `workspace_id` | проверено |
| Ошибка шлюза | Не JSON, например текст `404 page not found` | - | Несуществующие пути и бэкенды за прокси my.itmo.ru | проверено |

\* На живом аккаунте наблюдался HTTP 400 у БАРС `/journal/groups-and-flows` с `disciplineId` вместо `checkpointPlanId`; форма тела
взята из [../openapi/bars.yaml](../openapi/bars.yaml), сохранённого примера нет.

Правила разбора `ResultResponse`:

- HTTP 2xx не означает успех: проверять нужно `error_code`. Ошибка может прийти и с HTTP 200, и с HTTP 400.
- При ошибке `result` обычно `null`, но не всегда: выборность при закрытой кампании возвращает в `result` объект
  кампании вместе с кодом 112.
- `error_message` - текст для человека на языке `Accept-Language` (чаще всего по-русски); полагаться на точный текст
  нельзя, только на код.
- Сервер добавляет поля без предупреждения, поэтому схемы в [../openapi/my-itmo.yaml](../openapi/my-itmo.yaml)
  разрешают неизвестные свойства.

## Известные коды ошибок

| Код | Где | Значение | Статус |
|---|---|---|---|
| 100 | `/api/personalities/persons/{isu}` | Человека с таким номером ИСУ нет; HTTP 400, `result: null`, сообщение "Ошибка получения персонального инфо" | проверено |
| 101 | `/api/requests/form_update` | `Can not parse JSON`: тело не того формата (см. причуды) | проверено |
| 112 | `/api/election/students/*` | Выборность закрыта; `result` содержит объект кампании | проверено |
| 97 | `/api/facultative/`, `/api/intro/`: `current/`, `json/`, `limits/`, `schedule/user/` | Выборность ещё не открыта. В `status/` то же число приходит как `choice_status` при `error_code` 0 | проверено |
| 105 | `/api/facultative/description/`, `/api/intro/description/` | Нет описания дисциплин для пользователя | проверено |
| 114 | `/api/facultative/description/start/`, `/api/intro/description/start/` | Не найдено описание предмета | проверено |
| 114 | Запись на спорт | Нет доступа | сайт |
| 109 | `POST /api/facultative/booking/`, `POST /api/intro/booking/` | Успех, но есть пересечения в расписании: не ошибка | сайт |
| 130 | `DELETE /api/sport/sign/schedule/lessons` | Студент не записан | проекты |
| 135 | Запись на спорт | Выбор ещё не открыт | сайт |
| 137 | `POST /api/sport/sign/schedule/lessons` | Нельзя записать: `cannot enroll student: [daily limit\|overlapping enrollment\|weekly limit]` | проекты |

Выборность (`/api/election/students/`):

- `availability` отвечает `error_code` 0 и при закрытой кампании; состояние кампании - в `result.status` (текст) и датах.
- Остальные ручки при закрытой кампании отвечают 112.
- `order/` и `order/change` заменяют весь набор дисциплин или потоков, а не добавляют к нему;
  `group_flow_available_disciplines` только проверяет набор и ничего не сохраняет.
- `selected_flow_chains` отвечает 404 и устарел; актуальное дерево - `ordered_flow_chains`.
- Закрытые кампании факультативов и интро также встречаются с HTTP 403 (статус: сайт).

## Даты и время

Все сервисы живут по времени Europe/Moscow (UTC+3, без перехода на летнее время).

| Формат | Пример | Где | Статус |
|---|---|---|---|
| Дата ISO | `2026-09-01` | Query `date_start`, `date_end` расписания и спорта, `dateStart` бронирования, поля дат | проверено |
| Дата-время со смещением | `2026-09-01T10:00:00.000+03:00` | Выборность, факультативы, интро и другие поля даты-времени | проверено |
| Время `HH:mm` | `10:00` | Расписание (`time_start`, `time_end`), местное московское | проверено |
| `YYYY-MM-DD HH:mm` без зоны | `2026-09-01 10:00` | Тело создания брони (`start_datetime`, `end_datetime`), московское время | проверено |
| `DD.MM.YYYY`, `DD.MM.YYYY HH:mm` | `01.09.2026` | Значения полей `date` и `date_time` в `/api/requests/send` | проверено |
| `dd.MM.yyyy` в URL | `01.09.2026` | Параметр `GR_DATE` страниц ИСУ | проекты |
| Epoch миллисекунды | `1788000000000` | БАРС: `created_at`, `updated_at` | проверено |

## Причуды

- **`unavailable_reasons`** (спорт, `can_sign_in` и `sign_in_info`) бывает массивом строк, объектом с ключами-индексами
  (`{"0": "...", "1": "..."}`) или `null`. Нормализовать в список строк перед использованием. Сам `can_sign_in` не
  учитывает вместимость и квоты.
- **Случайные HTTP 500 на чтение.** Ручки бронирования (`/api/booking/rooms/roomsInCategory`,
  `/api/booking/dictionary/rooms/groups`) иногда отвечают 500, а повтор проходит. Повторять можно только GET;
  запись повторять нельзя: действие могло выполниться. itmo-mcp повторяет GET один раз через 300 мс.
- **`form_update`** (`POST /api/requests/form_update`) пересчитывает видимость полей заявки и ничего не сохраняет.
  Как делает сайт: `current_values` содержит все поля формы (`field_id`, `field_type`, `value`), а `changed_field` -
  числовой `field_id` изменённого поля. Неполное или неправильно оформленное тело получает код 101.
- **`Accept-Language`** со значением `ru` или `en` переводит названия и сообщения в ответах my.itmo.ru.
- **Нет CORS.** my.itmo.ru не отдаёт `Access-Control-Allow-Origin`; из браузера с другого домена API не вызвать,
  нужен серверный клиент или relay.
- **Чужие персональные данные.** `/api/booking/rooms/roomBookings` возвращает имена и номера ИСУ тех, кто забронировал
  помещения; при выдаче наружу их надо вырезать.
- **Фильтры статусов брони.** Сайт запрашивает `roomBookings` со статусами 1, 2, 5, 6, 8, приложение - 1, 2, 6, 8.
- **Завершающий слэш.** Часть путей объявлена со слэшем на конце (`/api/booking/bookings/`, БАРС
  `/users/current_user/`); используйте их как в спецификации, поведение без слэша не проверялось.
- **Период БАРС.** Данные БАРС отдаются за период из личных настроек пользователя; его смена через
  `POST /config/personal` меняет период и в веб-интерфейсе.

## Открытые вопросы

- Полный список кодов `error_code` нигде не опубликован; таблица выше собрана по наблюдениям и коду клиентов.
- Почему одни сервисы отвечают `error_code: null`, а другие 0, и бывает ли `null` при ошибке.
- Коды 130, 135, 137 и 114 для спорта взяты из кода клиентов и прошлых проектов, на живом аккаунте не воспроизводились.
