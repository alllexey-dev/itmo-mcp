## 1. Веб-клиент my.itmo.ru

- Сайт - Nuxt 2 (webpack). Чанки лежат в `https://my.itmo.ru/_nuxt/<hash>.js`; список всех чанков берётся из карты
  `chunkId -> hash` в runtime-чанке (он подключён в HTML страницы). Скачано 135 чанков.
- Из чанков извлечены вызовы API: поиск строковых литералов `/api/...` в вызовах `get/post/put/patch/delete`
  с ручной нормализацией конкатенаций (`.concat(x)` -> `{x}`). Результат: [data/web-api-calls.tsv](data/web-api-calls.tsv)
  (744 вызова в 30 разделах). Имена переменных в `{...}` восстановлены из минифицированного кода и условны.
- Там же найдены:
  - конфигурация модулей `@frontend/<module>` с полем `apiHost` - бэкенды за прокси сайта (см. [hosts.md](hosts.md));
  - переменные окружения Nuxt: `AUTH_SERVER_URL`, `AUTH_SERVER_REALM`, `AUTH_SERVER_CLIENT_ID`, `ALLOWED_AZP`,
    `API_SERVER_URL`, `FLAGSMITH_API_URL` (см. [auth.md](auth.md));
  - тела запросов на запись (спорт, бронирование, заявки, очереди, общежитие, ассистент).
- Как повторить: открыть `https://my.itmo.ru`, найти в HTML скрипты `/_nuxt/*.js`, в runtime-чанке взять карту
  чанков, скачать каждый `/_nuxt/<hash>.js`, затем искать `"/api/` и разбирать вызовы вокруг. Хэши меняются с каждым
  релизом сайта, поэтому результат привязан к дате.

## 2. Веб-клиент bars.itmo.ru

- Сайт - React (Create React App): `/static/js/main.<hash>.chunk.js` и lazy-чанки `/static/js/<n>.<hash>.chunk.js`,
  перечисленные в webpack-runtime. Разбирались `main` и 37 lazy-чанков.
- Дали: построение authorize-URL ITMO.ID для клиента `bars` (`response_type=code`, `scope=openid`, без PKCE),
  вызов `GET /rest/login?code=...&customRedirectUri=...`, пути журнала и настроек.
- Как повторить: так же, как для my.itmo.ru, но с `https://bars.itmo.ru/static/js/`.

## 5. Живая проверка

- Только чтение: `npm run verify:live` ([scripts/verify-live.ts](../scripts/verify-live.ts)) вызывает каждую
  GET-операцию [../openapi/my-itmo.yaml](../openapi/my-itmo.yaml) и [../openapi/bars.yaml](../openapi/bars.yaml)
  на аккаунте владельца и сверяет ответ со схемой. Выводит только operationId, HTTP-статус и места расхождений,
  без значений. На 2026-10-05 проходят все операции.
- Сырые ответы GET сохранялись локально только для изучения формы и в репозиторий не входят. Фикстуры тестов
  получены из них скриптом [scripts/sanitize-fixture.ts](../scripts/sanitize-fixture.ts): строки и числа заменены
  синтетическими значениями с сохранением форматов дат.
- Записи, одобренные владельцем 2026-10-05; все прошли и откатаны:

| Действие | Откат | Результат |
|---|---|---|
| Запись на разовое занятие спорта | Отписка | Попытка вернулась |
| Создание брони коворкинга | Отмена брони | Статус стал `Отменена` |
| Подача заявки на справку (шаблон 2706) | Отмена заявки | Заявка отменена |

- Вход без пароля по cookie `KEYCLOAK_IDENTITY` проверен для клиентов `student-personal-cabinet` и `bars`.

## 6. Сетевая панель браузера

На my.itmo.ru в DevTools снят запрос `POST /api/requests/form_update`, который сайт отправляет при изменении поля
заявки: в `current_values` уходят все поля формы, `changed_field` - число. Подробности в
[conventions.md](conventions.md).

## Что не входит в репозиторий

Скачанные бандлы, APK и его разбор, сырые ответы живого аккаунта, HAR-записи и токены. Персональные данные
в репозиторий не попадают.
